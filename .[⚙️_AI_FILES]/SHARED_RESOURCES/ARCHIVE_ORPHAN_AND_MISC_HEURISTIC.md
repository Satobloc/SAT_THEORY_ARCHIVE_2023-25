# Archive Orphan and Miscellaneous-Source Heuristic

Status: durable archive-navigation guidance

## Principle

Especially in the main SAT archive, folder labels are weak evidence of relevance. The repository is substantially a developmental document dump assembled across several years and many phases. Files were often saved pragmatically, copied, moved incompletely, mislabeled, or left in temporary/catch-all locations. Important work can therefore survive in folders named `MISC`, `miscellaneous`, `old`, `other`, `unsorted`, unclear abbreviations, or apparently peripheral categories.

Do **not** let folder labels function as exclusion filters.

Material that was temporarily lost, forgotten, or not recognized as important when it was saved may be disproportionately likely to survive in exactly these catch-all locations.

## Operating consequences

When surveying, indexing, reconstructing provenance, searching for derivations, or auditing novelty:

- treat folder names as navigation hints, not relevance judgments;
- sample and, where feasible, index deep miscellaneous/unclear/catch-all folders rather than excluding them;
- search by content, chronology, equations, distinctive phrases, filenames, and cross-document references in addition to folder path;
- explicitly record folders that are only shallowly indexed or sampled so later readers do not mistake silence for absence;
- when an important source is found in an unexpected location, add a breadcrumb or cross-reference rather than moving or rewriting the historical source without need;
- preserve the distinction between where work was originally done, where it was later summarized, and where a surviving copy happens to be stored.

## Orphan concept

An **archive orphan** is a file or source fragment whose current location, filename, labeling, chronology, or linkage does not adequately expose its relationship to the developmental record.

Possible orphan indicators include:

- a file in a catch-all or apparently unrelated folder whose contents match a major SAT/H(s)H development;
- a focused document with no known FULL_CONVO source;
- a conversation-derived document whose originating conversation has not yet been located;
- a duplicate or near-duplicate whose source lineage is unclear;
- a file containing significant mathematics or conceptual development absent from the current derivation/index maps;
- a dated or historically important item whose chronology conflicts with its folder or filename;
- a file referenced elsewhere in the archive but not linked back from current indexes;
- a source that appears to bridge two developmental phases but is currently categorized under only one.

## Recommended orphan workflow

1. **Detect** — identify orphan candidates during structural indexing, content search, bibliography work, provenance crosswalks, and deep-folder sampling.
2. **Record** — add candidates to a separate orphan ledger rather than silently reclassifying them.
3. **Cross-reference** — link each candidate to related FULL_CONVOS, focused documents, equations/derivations, external literature, and later synthesis where evidence supports the connection.
4. **Score confidence** — distinguish exact provenance, strong textual/chronological match, thematic relation, and unresolved suspicion.
5. **Leave in place by default** — historical location is itself provenance. Prefer breadcrumbs, indexes, aliases, and crosswalks over moving source artifacts.
6. **Resolve** — when provenance becomes clear, mark the orphan as resolved but retain the original record and source location.

Suggested orphan-ledger fields:

- orphan ID
- exact repository/path
- artifact type
- current folder label
- detected date evidence
- why it appears orphaned
- related concepts/claims/equations
- candidate source conversation(s)
- candidate downstream document(s)
- duplicate/lineage relationships
- confidence
- read status
- resolution status
- reviewer notes

## Search bias warning

Existing indexes may be incomplete, especially at depth. Search-index absence is not archive absence. Periodic deep traversal and deliberate miscellaneous-folder core sampling should remain part of the archive audit.
