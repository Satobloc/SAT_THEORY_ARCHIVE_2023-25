# Memory Credenza: archive-side wayfinding and coverage model

**Date:** 2026-11-19  
**Status:** Transferable experimental method for archive navigation and review; not a theory claim and not a completeness guarantee.

The [HsH Memory Credenza model](https://github.com/Satobloc/HsH/blob/main/WORKSPACES/COMMON/MEMORY_CREDENZA_MODEL_2026-11-19.md) offers a compact way to think about continuity and attention across a large repository-backed environment.

## Key, Credenza, Castle

- **Key:** the tiny boot/continuity capsule. It identifies the remit, immediate place, re-entry sequence, and pointer to the Credenza. It should stay small.
- **Credenza:** a compact adaptive router, with drawers/cubbies that expose purpose, route, trigger, status, last meaningful inspection, and return cue.
- **Castle:** the full archive and connected research environment: original records, historical versions, source histories, indexes, extraction manifests, tools, workflows, derived outputs, and interpretive/research modules.

A cubby is an access point, not a duplicate repository. The Credenza should help a worker find and use the correct archive layer without flattening the difference between source artifacts, machine-generated navigation, reviewed metadata, and interpretation.

## Useful archive cubbies

Possible compartments include original sources and provenance; historical formulations and chronology; open questions and competing interpretations; reviewed findings and corrections; indexes/manifests/extraction state; research tools and workflows; cross-repository connections; underexplored folders or source strata; and deferred work with explicit return conditions.

For archive material, preserve granular exposure states. For example: **located**, **indexed**, **metadata-only**, **partially read**, **fully read**, **unreadable/OCR-needed**, **not yet examined**, or **duplicate lineage identified**. A file's presence or index entry is not evidence that it was read, understood, relevant, or supportive. Keep exact paths, commit/blob or content hashes, source locators, read extents, and next cursors where applicable.

## Tick, tock, and sampling

The tick is the compact current-place/return marker, such as `PIN | NOW | NEXT | RETURN`. The tock is a bounded operation that leaves a durable, recorded result and next cursor. A repository commit or tool call alone does not establish that meaningful inspection occurred. A heartbeat, where used, should report human-directed archive activity separately from automated runs.

A future **neglect sampler** could combine:
1. coverage rotation across folders, time periods, source types, historical branches, indexes, and review states whose meaningful-inspection date or coverage status makes them due; and
2. stratified random selection that sometimes draws from less-used or weakly mapped strata, including a stratum for poorly inventoried material.

The sampler must inspect originals or clearly state that it only sampled metadata. It should record the sampling frame/version, method/seed where practical, selected item, exact source pointer, inspection extent, result, action, and return cue. Random selection is not a relevance judgment. A sample does not make an item important, and failure to select an item is not evidence against it. Preserve source artifacts unchanged; use derived/administrative layers for sampling state and results.

## Caretaker and limits

A caretaker pass can check whether archive pointers resolve, coverage dates and read states are stale, new tools or source collections lack routing, strata are missing from the sampling frame, and accumulated machinery is becoming redundant or burdensome. It should surface recommendations rather than silently rewrite archive history, infer relevance, alter source material, or change project priorities.

Start with navigation cards and links to the systems that already exist. Build a sampler only after the inventory is adequate to define meaningful strata. Consider automation only after a bounded, auditable pilot shows useful new coverage or other durable value. No automation or schedule change is authorized by this note.
