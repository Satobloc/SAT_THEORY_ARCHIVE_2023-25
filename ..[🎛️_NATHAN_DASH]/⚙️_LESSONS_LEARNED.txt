LESSONS LEARNED

Purpose:
Record practical archive-operation problems and their solutions so future Nathan/AI sessions do not rediscover them from scratch.

Standing habit:
- When a problem occurs, read this file before troubleshooting too deeply.
- When a solution is found, add a short entry.
- Keep entries practical and reusable.
- If GitHub access is needed and unavailable, remind Nathan to make the GitHub tool available.

Entry format:

------------------------------------------------------------

NOTES:
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-13
PROBLEM: Manual workflow_dispatch created confusion because a workflow-file update triggered Archive Admin, while the intended new workflow had not actually performed the archive operation.
CAUSE: GitHub Actions UI and workflow names can be misleading when one workflow updates or responds to another workflow file. Manual triggers also cannot reliably be initiated by ChatGPT through the current connector surface.
SOLUTION: Treat request-file commits as the standard operational trigger. ChatGPT/Gitkeeper updates .[⚙️_AI_FILES]/REQUESTS/archive_admin_task.txt with an explicit TASK block. Archive Admin runs on push, reads the request, executes the task, writes logs, and commits outputs with [skip archive-admin]. Manual workflow_dispatch remains fallback/debug only.
APPLIES TO: Archive Admin, full archive indexing, future tagging, extraction, cleanup, and other repo-local tools
NOTES: Proven full-archive index path: request file → Archive Admin → TARGET: . → committed index/log outputs. Future durable tools should be implemented as Archive Admin task modes or request-triggered wrappers, not manual-only workflows.
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-13
PROBLEM: Semantic tagging was being considered before a current archive map existed.
CAUSE: Tagging without a current structural index would force the tagger to discover and classify the archive at the same time, making provenance, coverage, and confidence harder to audit.
SOLUTION: Index first, tag second. Run a structural index pass first, then run tagging as a separate layer over the indexed file list with explicit provenance and confidence.
APPLIES TO: folder indexing, full archive indexing, semantic tagging, future SATopedia/catalog work
NOTES: Structural indexes describe what exists. Tagging should describe what the indexed files appear to mean, with uncertainty preserved.
------------------------------------------------------------
