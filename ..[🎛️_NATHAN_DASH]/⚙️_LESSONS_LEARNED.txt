LESSONS LEARNED

Purpose:
Record practical archive-operation problems and their solutions so future Nathan/AI sessions do not rediscover them from scratch.

Standing habit:
- When a problem occurs, read this file before troubleshooting too deeply.
- When a solution is found, add a short entry.
- Keep entries practical and reusable.
- If GitHub access is needed and unavailable, remind Nathan to make the GitHub tool available.

Entry format:

------------------------------------------------------------
DATE:
PROBLEM:
CAUSE:
SOLUTION:
APPLIES TO:
NOTES:
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-07
PROBLEM: GitHub Actions workflow failed to parse path filters using dashboard/AI folder names with brackets and emoji.
CAUSE: GitHub Actions path filters use glob syntax. Square brackets in paths can be interpreted as character classes and can make patterns invalid.
SOLUTION: Use workflow_dispatch only for dashboard/admin workflows, or trigger from plain ASCII paths.
APPLIES TO: .github/workflows/*.yml
NOTES: Manual trigger is safer for archive admin operations anyway.
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-07
PROBLEM: ChatGPT could write some repo files but could not run Python directly inside the GitHub repository.
CAUSE: GitHub connector file access and GitHub Actions execution are separate capabilities.
SOLUTION: Use GitHub Actions workflows that run repo-local Python tools from request/control files. ChatGPT updates requests; Nathan runs workflow; workflow logs results.
APPLIES TO: archive admin, indexing, extraction tooling
NOTES: This is now the standard architecture pattern.

DATE: 2026-06-07
PROBLEM: ChatGPT may not always have the GitHub tool available in a given session.
CAUSE: Tool availability can vary by session/context, and GitHub access may not be enabled or visible.
SOLUTION: If archive work requires GitHub and the tool is missing, remind Nathan to make the GitHub tool available.
APPLIES TO: any archive operation requiring repo reads/writes
NOTES: Do not assume GitHub access exists just because previous sessions had it.

DATE: 2026-06-07
PROBLEM: Direct GitHub connector edits can be inconsistent or blocked, especially for operational manifests or cleanup-looking content.
CAUSE: Connector write permissions and safety checks may vary by path/content/context.
SOLUTION: Prefer the Archive Admin request workflow. ChatGPT updates a small request file when possible; Nathan runs the existing Archive Admin workflow; the workflow performs bounded operations and writes logs.
APPLIES TO: archive admin, cleanup, dashboard edits, AI tooling edits
NOTES: Stable edit access should mean request-driven workflow access, not relying on direct connector writes.
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-07
PROBLEM: Workflow warnings about Node.js 20 deprecation appeared during Archive Admin runs.
CAUSE: GitHub Actions checkout/setup-python actions targeted Node.js 20, but GitHub is forcing Node.js 24.
SOLUTION: The warning is not currently a failure. Keep FORCE_JAVASCRIPT_ACTIONS_TO_NODE24 enabled in workflow env and monitor future action-version compatibility.
APPLIES TO: .github/workflows/archive-admin.yml and other workflows using actions/checkout or actions/setup-python
NOTES: Do not treat the deprecation warning as a failed run unless workflow logs show actual failure.
------------------------------------------------------------

------------------------------------------------------------
DATE: 2026-06-07
PROBLEM: Archive Admin initially required Nathan to manually click Run Workflow after ChatGPT updated the request file.
CAUSE: The workflow was configured as workflow_dispatch only, so request-file commits did not automatically execute the admin tool.
SOLUTION: Configure Archive Admin with both workflow_dispatch and push triggers, and guard the job with if: github.actor != 'github-actions[bot]' to prevent recursive self-triggering. ChatGPT request-file commits can then trigger the workflow automatically; workflow-generated commits are ignored.
APPLIES TO: .github/workflows/archive-admin.yml, request-driven archive tools
NOTES: Preferred pattern is now: ChatGPT updates request file → push triggers Archive Admin → Archive Admin logs results → ChatGPT verifies logs. Use manual workflow_dispatch as fallback.

DATE: 2026-06-07
PROBLEM: A legacy workflow continued failing with "push event contained invalid paths patterns" even after Archive Admin was fixed.
CAUSE: .github/workflows/index_folder.yml still used push.paths filters that referenced bracketed/emoji dashboard and AI folder paths. GitHub Actions treats paths filters as glob patterns, where square brackets have special meaning. The workflow also referenced stale folder names such as .[🎛️_DASHBOARD] rather than the current ..[🎛️_NATHAN_DASH].
SOLUTION: Disable or retire legacy workflows with bracket/emoji push.paths filters. Prefer Archive Admin TASK: INDEX_FOLDER for indexing. If push triggers are needed, avoid paths filters on bracketed/emoji folders; use a broad push trigger plus github-actions[bot] loop guard, or trigger from plain ASCII request paths.
APPLIES TO: .github/workflows/index_folder.yml and any workflow using push.paths with bracketed/emoji paths
NOTES: Similar filenames are messy but were not the root cause. The root cause was invalid glob-style path patterns in workflow YAML.
